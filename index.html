Cognition AI (Devin) & the Claude Expansion Blueprint

How I would run this account as Anthropic's enterprise AE. Devin already runs on Claude — Cognition said so when it rebuilt Devin for Sonnet 4.5. So the play is not migration; it is consumption depth and defence: deeper prompt caching, a procurement route through the AWS relationship Cognition just signed, and a credible answer to the in-house SWE-1.5 / SWE-2 models that compete for the same tokens.

Thesis: at Devin's scale, the cache-read line is the margin. Every point of cacheable-prefix share is worth more than any list-price discount, and it is the one lever Cognition's own models cannot copy without rebuilding Claude.

02 · Technical wedges

Three hypotheses I would bring to the first technical call

Written as hypotheses to validate with Cognition's team, not as a lecture. Each ends with what I would want to check.

One deliberate pass beats N sampled ones

Agent harnesses historically bought reliability with self-consistency: sample a plan 3–5 times, vote, re-read the repo each time. Extended thinking moves that deliberation inside a single turn, with a budget the harness controls. The context is read once; the thinking tokens are billed as output.

HypothesisDevin's planning stage can replace multi-sample voting with a tuned thinking budget per task class, cutting context re-reads while keeping the +18% planning lift Cognition measured on Sonnet 4.5.

Napkin math at 60K context: 3 samples re-read 180K input tokens; one pass with an 8K thinking budget reads 60K and writes 8K. At $2 / $10 that is roughly $0.36 vs $0.20 per planning step before caching — and with 90% cache reads the single-pass figure drops further because the one read is mostly cached.

  • Which task classes still use multi-sample planning, and what is their share of loops?
  • Is the thinking budget fixed or adaptive — and does it correlate with Junior Developer Eval difficulty?
  • Does the 200K cap stay necessary once thinking replaces re-reads?

Devin's prompt stack maps onto four cache breakpoints

Caching rewards stable prefixes. A coding agent's prompt is unusually prefix-stable: system instructions and tool schemas never change inside a session; the repo map and DeepWiki-style summaries change rarely; only the latest turn is new. Anthropic allows up to 4 explicit breakpoints with a 20-block lookback, 512-token minimum on the current models, and a TTL that refreshes on every read.

HypothesisDevin's codebase index (Devin Wiki / repo map) and tool definitions can sit behind breakpoints 1–2 and reach a 90%+ hit rate on multi-turn sessions; the 1-hour TTL pays for itself on any session with gaps longer than five minutes between turns (human review, CI waits).
  • Where does session state currently live — in the prompt (cacheable) or re-fetched per turn (not)?
  • Typical gap between turns while Devin waits on CI or a human: under or over five minutes?
  • Does parallel-Devin fan-out share a prefix, so one write serves many readers?

Sources: prompt caching docs · Devin 2.0: Devin Wiki, Devin Search, parallel Devins

Buy Claude where Cognition already sells Devin

Cognition's production environment is AWS (its own security docs say so), it signed a multi-year Strategic Collaboration Agreement with AWS in September 2026, and Devin is sold on AWS Marketplace. Bedrock has price parity with Anthropic direct — Sonnet 5.5 at $2 / $10, cache reads at $0.10 after the October 7 cut — so routing a Claude commit through the AWS relationship costs nothing on list price and can remove a vendor security cycle.

HypothesisA Marketplace private offer for Claude (Bedrock or Claude Platform on AWS, billed in CCUs) would count toward Cognition's AWS commitment and reuse the SOC 2 / ZDR paperwork already on file — collapsing procurement from a new-vendor review to an addendum. Whether an EDP exists, and whether this drawdown applies, is exactly what discovery must confirm.
  • Direct Anthropic API, Bedrock, or both today — and which one carries the volume?
  • Is there an AWS commitment the SCA sits under, and does Marketplace spend count toward it?
  • Batch on Bedrock is N/A for the 5.5-generation models: does any batch-eligible workload need to stay direct?
